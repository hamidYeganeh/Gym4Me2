# T024-a — کنترل حریم خصوصی وب، ۱۹ اکتبر ۲۰۲۶

این برش وب پذیرفته شد؛ T024 والد، PH0 و PH1 کامل بازند. رضایت در آزمون، دادهٔ ازپیش‌آمادهٔ fixture بود؛ هیچ توافقی برای کاربر واقعی پذیرفته نشد.

## تغییر

در جزء مشترک `packages/ui/src/account/privacy.tsx`:

- خطای درخواست حذف داخل دیالوگ فعال نمایش داده می‌شود؛ قبلاً پشت دیالوگ و خارج از دسترس قرار می‌گرفت.
- قفل هم‌زمان فرمان‌ها پیش از اولین await برقرار می‌شود. هنگام درخواست، بستن دیالوگ با Escape/کلیک بیرون/دکمهٔ بستن متوقف است.
- فرم با ذخیرهٔ رضایت دوباره mount نمی‌شود. تغییر واقعی مقدار تأییدشدهٔ سرور، checkbox را هم‌زمان می‌کند؛ بازخوانی نامرتبط پیش‌نویس را حفظ می‌کند. این مقایسه مانع باقی‌ماندن رضایت قدیمی پس از لغو در نویسندهٔ دیگر می‌شود.
- بازگردانی فوکوس منتظر commit کنترل فعال پس از busy می‌ماند؛ frame لغوشدنی است و تغییر مسیر، سطح غیرفعال یا فوکوس جدید کاربر را رعایت می‌کند. بازگردانی یک‌مرحله‌ایِ اولیه در آزمون واقعی ناپایدار بود و جایگزین شد.
- شناسهٔ checkboxها برای هر فرم یکتا است؛ labelها و دکمه‌های فرم/دیالوگ حداقل ارتفاع۴۴ دارند. ارتفاع دیالوگ محدود و محتوا قابل اسکرول است.

بازبینی استاندارد و spec انجام شد. یک regression در هم‌زمان‌سازی رضایت پیدا و پیش از build نهایی رفع شد؛ بررسی کد اصلاح‌شده یافتهٔ قابل اقدام تازه نداشت. این گزارش، گزارش یک security scan کامل نیست.

## آزمون واقعی روی نسخهٔ نهایی

ورزشکار با NestJS و PostgreSQL اختصاصی `gym4me_ph1privacy_1a14e17_test`، SMS ساختگی و حساب بی‌مسئولیتِ مخصوص آزمون بررسی شد. مقدار رضایت و کهنگی/تازگی نشست در DB فقط برای همین حساب تنظیم شدند؛ کلیک روی پذیرش سیاست و پردازش حذف دائمی در مرورگر انجام نشد.

## نگاشت صفحه به API اجراشده

صفحهٔ `/profile/settings/privacy` ← `MobileAccount` ← `AccountPrivacy` ← hookهای profile ← `AccountPrivacyController`/`PrivacyService`:

| روش و endpoint در `/api/v1` | حالت مشاهده‌شده |
| --- | --- |
| GET `profile/account/privacy` | 200؛ رضایت، نمایش عمومی، امکان درخواست و وضعیت حذف |
| POST `profile/account/privacy/preferences` | 201؛ بازاریابی و خصوصی‌کردن نام |
| POST `profile/account/privacy/deletion` | 409 نشست قدیمی و201 درخواست موفق |
| POST `profile/account/privacy/deletion/cancel` | 201 و وضعیت cancelled در DB |
| GET `profile/account/privacy/export` | 200، دانلود و اعتبارسنجی JSON واقعی |

[رخدادهای HTTP](baselines/ph1-privacy-2026-10-19/http.json) فقط method/path/status دارند. buffer اولیه truncated بود؛ این رخدادها شاهد پاسخ‌های ثبت‌شده‌اند و مبنای ادعای شمار کامل درخواست‌ها یا نبود درخواست اضافی نیستند. UI، فایل دانلود و DB شاهدهای مستقل نتیجه‌اند.

## بررسی‌ها و buildها

- ۳۲ آزمون integration هویت/حریم خصوصی پاس: اطلاعات اختیاری و پنهان‌سازی، رضایت نسخه‌دار، خروجی scoped بدون credential، محدودیت مسئولیت/نشست، درخواست/لغو، پاک‌سازی و replay دفتر حذف. اجرای انتخابی ابتدا به fixture ساخته‌شده در تست قبلی وابسته بود و شکست خورد؛ کل suite سپس بدون skip پاس شد.
- ۸ آزمون native-export/session-navigation و۲ آزمون i18n پاس؛ مجموع این نوبت **۴۲ آزمون یکتا**. آزمون adapter جای خروجی دستگاه نیست.
- lint نهایی، copy، محافظ۵۹ فایل و diff-check پاس‌اند. typecheck جداگانه با heap۳۸۴ تمام نشد؛ TypeScript هر سه build نهایی با heap۶۴۰ موفق شد.
- ساخت ترتیبی، یک worker، cache خاموش و nice10 بود. build نهایی ورزشکار زمان بیشتری از ساخت اولیه برد؛ فرایند زنده حفظ شد و موازی دوباره اجرا نشد.

## پاک‌سازی و پذیرش باز

API خروج0 و App خروج130 دادند. سازمان/کاربر/درخواست حذف fixture پیش از DROP برابر `0|0|0` و سازمان/کاربر suite API برابر `0|0` بودند. هر دو DB اختصاصی حذف و کانتینر test به وضعیت اولیهٔ خاموش بازگردانده شد؛ storage از قبل روشن دست‌نخورده ماند. فایل دانلود فقط پس از تطبیق accountId با fixture حذف شد. تب آزمون بسته، viewport و نمایش مرورگر بازگردانده شدند. مشاهدهٔ cookieها فقط cookie اولیهٔ نامرتبط را برگرداند؛ همان حفظ شد و حذف cookie ورود ادعا نمی‌شود. با حذف DB، اعتبار fixture نیز دیگر قابل استفاده نیست.

پذیرش کامل T024 به باقی فلوهای پروفایل/رضایت، دامنهٔ تمام رابط‌ها و خروجی واقعی native نیاز دارد. Q09 فعلاً پیش‌فرض قابل تنظیم پایلوت است و سیاست قطعی انتشار نیست. دستگاه، HTTPS/association دامنه، remote CI، بکاپ خارج از این مک، صفحه‌خوان و معیارهای کامل PH0 طبق backlog بازند؛ این برش آن‌ها را حذف نمی‌کند.
