# انتخاب بستهٔ معتبر در خرید وب — ۱۷ اکتبر ۲۰۲۶

ادامهٔ هدف طبق محدودیت فعلی کاربر فقط روی وب انجام شد. Docker، PostgreSQL، staging، S3 و دستگاه دست‌نخورده‌اند. هیچ quote، سفارش، رزرو، پرداخت یا نشست ساخته نشد؛ رضایت شرایط هم ارسال نشد. این بررسی، پذیرش فنی فاز یا تراکنش واقعی نیست.

## اصلاح محصول

فیلتر قبلی بسته فقط status=active و سازمان/شعبه را کنترل می‌کرد. منطق جدید در `lib/checkout-memberships.ts` اعتبار انحصاری تاریخ پایان، freezeUntil، ماندهٔ `granted − consumed − held` و تعداد جلسات کل دورهٔ دریافت‌شده را نیز بررسی می‌کند. بستهٔ نامحدود ماندهٔ null دارد؛ منقضی/فریز یا بستهٔ شعبه/سازمان دیگر پیشنهاد نمی‌شود. مانند قرارداد جاری سرور، اعتبار در زمان خرید بررسی می‌شود؛ سیاست تازه‌ای برای اعتبار تا تاریخ آخرین جلسه اختراع نشده است. سرور همچنان مرجع نهایی و دارای قفل است؛ فیلتر رابط، حق استفاده یا ظرفیت نگه نمی‌دارد.

گزینهٔ قابل انتخاب مانده یا نامحدود بودن را با عدد محلی نشان می‌دهد. توضیح به select از طریق aria-describedby و شناسهٔ useId متصل است تا با نسخهٔ خروجی SSGOI تداخل نکند؛ لینک عضویت‌ها بیرون label است. اگر انتخاب قبلی پس از دریافت داده دیگر معتبر نباشد، به پرداخت بدون بسته تبدیل نمی‌شود: گزینهٔ غیرفعال با پیام، aria-invalid/aria-errormessage و غیرفعال بودن ادامه نمایش داده می‌شود. این شاخهٔ تغییر داده در صفحهٔ باز هنوز مرورگری پذیرفته نشده است.

انتخاب بسته، تخفیف و رضایت هنگام quote/checkout در حال ارسال غیرفعال‌اند. این رفتار به جلوگیری از تغییر ورودی در میانهٔ درخواست کمک می‌کند؛ timing آن با درخواست واقعی هنوز آزموده نشده است. state فرم همچنان با service/occurrence کلید می‌خورد. کارت‌های club/coach، جزئیات باشگاه، Kit و CSS عمومی تغییر نکردند؛ guard۵۹ فایل پاس است.

## ابزار فقط‌خواندنی و امنیت دامنهٔ آزمون

fixture قبلی به دو حالتِ صریح `checkout-read` و `checkout-read-error` گسترش یافت. اولی فقط GET مسیر دقیق `sports/account/memberships` را با هشت DTO مصنوعی پاسخ می‌دهد؛ دومی فقط همان مسیر را503 می‌کند و خدمت عمومی را سالم نگه می‌دارد. profile/auth و سایر حساب‌ها در همهٔ حالت‌ها401 هستند. در حالت عادی populated، خواندن عضویت نیز همچنان401 است. هیچ هویت یا Cookie صادر نمی‌شود و FavoritesSync وارد حساب ساختگی نمی‌شود. تمام POST/PATCH/PUT/DELETE، از جمله quote و checkout و callback، پیش از route به405 می‌رسند. داده یا بدنهٔ خصوصی ذخیره/لاگ نمی‌شود. این حالت صرفاً شبیه‌سازی دادهٔ یک query برای مشاهدهٔ فرم است، نه ورود موفق یا تست مجوز بک‌اند.

اجرای fixture از apps/api:

```sh
GYM_WEB_READ_FIXTURE=true WEB_READ_PORT=7488 WEB_READ_SCENARIO=checkout-read \
NODE_OPTIONS=--max-old-space-size=96 \
node --import tsx ../../apps/application/scripts/web-read-fixture.mts
```

آدرس API هنگام build خروجی `.next-qa` روی7488 ثبت شده است. برای API واقعی باید با آدرس صحیح rebuild شود؛ این fixture از test/scripts به bundle صفحه import نمی‌شود.

## شواهد آزمون

۲۱ آزمون با heap۱۲۸MiB و test-concurrency=1 در حدود۴۹۲ms پاس شدند: شش مورد انتخاب سانسِ قبل، پنج مورد مانده/بسته و ده مورد HTTP fixture. آزمون‌های تازهٔ HTTP نشان دادند opt-in خواندن DTO، profile/auth یا سفارش را مجاز نمی‌کند و نوشتن همچنان405 است. این تعداد، آزمون‌های مستقل PostgreSQL یا رقابت آخرین جلسه نیست.

ESLint هفت فایل مرتبط پاس شد. یک build ورزشکار با یک worker، heap۵۱۲MiB، Webpack cache خاموش و بدون fixture/preview هم‌زمان موفق بود؛ compile۹٫۹s، TypeScript۸٫۵s و۶۴ صفحه. سپس فقط preview۲۵۶MiB و fixture۹۶MiB اجرا شدند. فضای آزاد ابتدای این برش۲٫۰GiB بود؛ فایل یا کش پروژهٔ دیگری پاک نشد.

[ماتریس](checkout-memberships-web-matrix-2026-10-17.json): ۳۶ مورد یکتا = کلاس/دوره/خرید بسته × دو زبان × دو تم × سه عرض۳۶۰/۳۹۰/۴۳۰. همه یک main فعال، بدون سرریز افقی، گزینه‌های با شناسهٔ دقیق موردانتظار و توضیح متصل داشتند. برای کلاس سه بسته و برای دوره هشت‌جلسه‌ای دو بسته وجود داشت؛ خرید بسته select مصرف بسته نداشت. بررسی قیمت در نمونه‌های معتبر فعال و رضایت/ادامه بدون quote غیرفعال بودند. این ماتریس DOM است؛ مرور تصویری کامل یا صفحه‌خوان نیست.

از مسیر واقعی رابط، در کلاس یک بسته و کد DEMO انتخاب شد، با Back به خدمت/فهرست رفتیم و دوره را انتخاب کردیم. انتخاب بسته و کد خالی شدند و فقط بستهٔ هشت‌جلسه‌ای و نامحدود ماندند. بعد از گذار، توضیح select فقط یک id هم‌نام در DOM داشت. رضایت و quoteِ پذیرفته‌شده در این آزمایش ساخته نشدند، پس reset آن‌ها از این شاهد نتیجه نمی‌شود.

دو مورد اضافه با DTO بستهٔ موفق، غیرفعال بودن بررسی قیمت برای سانس پُر و منبع ناموجود را در UI تأیید کردند. سپس خواندن بسته503 شد: قیمت و اطلاعات عمومی باقی ماندند، select/کد تخفیف نشان داده نشد و خطا با Retry نمایش داده شد؛ خطا به «بسته نداری» تعبیر نشد. پس از Retry، فوکوس روی دکمه و aria-busy=false بود. یک press End ابزار timeout شد؛ snapshot بعدی صفحه و فوکوس سالم را نشان داد و همان وضعیت موجود ثبت شد.
