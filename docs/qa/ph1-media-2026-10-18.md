# پذیرش زیرساخت فایل PH1 — ۱۸ اکتبر ۲۰۲۶

T019 با object storage منتخب محلی SeaweedFS، metadata، محدودیت تصویر، مالکیت و حذف پذیرفته شد. محدودسازی اعتبار S3 در production، انتشار دامنه یا بکاپ مستقل در این برش پذیرفته نشده‌اند؛ T026/T029 و پذیرش کامل PH0/PH1 بازند.

## تغییر و قرارداد

پیش‌نمایش قبلاً فقط عضویت مجموعه را می‌سنجید. اکنون مدیر/پذیرش/مالی محدود فقط جلد، لوگو، گالری مشترک یا تصویری با ارجاع در شعبهٔ مجاز و آرشیونشده را می‌خوانند. رسانهٔ بدون ارجاع و تصویر صرفاً متعلق به شعبهٔ دیگر403 می‌گیرند. مالک و کارکنان همهٔ شعب به رسانه‌های مجموعه دسترسی دارند؛ ادمین از مسیر اختصاصی با مجوز پلتفرم استفاده می‌کند. شناسهٔ رسانهٔ مجموعهٔ دیگر404 می‌گیرد. تغییر grant یا حذف عضویت روی درخواست بعدی اعمال می‌شود؛ URL صادرشده تا۶۰ثانیه معتبر است.

فایل ورودی JPEG/PNG/WebP تا۱۰MiB است؛ decoder با سقف۴۰میلیون پیکسل و منع تصویر چندصفحه‌ای اجرا می‌شود. خروجی با چرخش و ابعاد حداکثر۲۴۰۰ به WebP تبدیل و metadata دوربین حذف می‌شود. شناسه، مجموعه، بارگذار، object key، نوع، حجم، ابعاد و alt در PostgreSQL ذخیره می‌شوند. URL عمومی فقط رسانهٔ مرجع‌دار کاتالوگ منتشرشده را سرو می‌کند. فایل ارجاع‌شده حذف نمی‌شود؛ شکست storage هنگام حذف، metadata را نگه می‌دارد تا تلاش بعدی ممکن بماند. پاک‌سازی دوره‌ای بدون ارجاع/orphan با grace و dry-run نیز موجود است.

## شاهد اجرا

کد و آزمون پیش از اجرای suite تکمیل شدند. فقط API درون آزمون اجرا شد؛ وب/native اجرا یا rebuild نشدند.

| بررسی | نتیجه |
| --- | --- |
| `tsc --noEmit` در API، heap۶۴۰MiB | exit0 |
| ESLint دو فایل تغییرکرده با تنظیم API | exit0 |
| Jest کاتالوگ، `--runInBand`، heap۶۴۰MiB | ۴۰/۴۰، اجرای نهایی۸٫۵۵۱ثانیه |
| محافظ طراحی | ۵۹ فایل بدون تغییر |

آزمون‌ها روی PostgreSQL مستقل `gym4me_ph1media_1a14e17_test` و bucket تصادفی `gym4me-catalog-<uuid>` با S3 واقعی اجرا شدند. suite هم انتشار/خصوصی‌شدن، حذف فایل مرجع‌دار، retention و dry-run/idempotence موجود را بررسی کرد و هم موارد تازهٔ زیر را:

- دریافت واقعی URL امضاشده200 و برابری بایت‌ها با object؛ حذف query امضا از همان URL،403.
- رد SVG، بایت نامعتبر، فایل مفقود و بیش از۱۰MiB؛ ثبت درست metadata و WebP واقعی.
- JPEG کوچک با EXIF معلوم و خروجی فاقد EXIF/XMP/IPTC.
- سه نقش محدود، دو شعبه، رسانهٔ مشترک/مجاز/غیرمجاز/بدون ارجاع و شناسهٔ خارجی؛ جلد/لوگو، آرشیو شعبه، حذف grant، گسترش همهٔ شعب و حذف عضویت با همان نشست.
- شکست کنترل‌شدهٔ متد حذف با503، حفظ metadata و object، سپس حذف موفق و نبود object. این مورد تزریق شکست در adapter بود؛ قطعی واقعی سرویس شبیه‌سازی نشد.

logهای اولیه و نهایی: `.artifacts/ph1-media-2026-10-18/clubs.log` و `clubs-final.log`. bucket و objectهای اختصاصی در teardown پاک شدند؛ دیتابیس موقت نیز DROP شد. containerهای موجود و دادهٔ اصلی تغییر نکردند.

این برش آزمون decoder برای فایل واقعاً۴۰میلیون‌پیکسلی، ممیزی امنیتی کامل، نمایش UI بارگذاری یا عملیات production نیست. معیارهای دیگر به دامنهٔ خودشان در backlog باقی‌اند؛ T013 والد همچنان به دستگاه و باقی فلوهای هویت نیاز دارد.
