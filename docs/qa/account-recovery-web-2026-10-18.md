# بازیابی ورود در وب — ۱۸ اکتبر ۲۰۲۶

ادامهٔ PH0/PH1 و رابط PH2 با دستور «فعلاً فقط بررسی‌های وب را ادامه بده». Docker، دیتابیس، S3، staging و دستگاه اجرا یا بازراه‌اندازی نشدند. این گزارش پذیرش فاز نیست.

## اصلاح‌ها

- ورود فشردهٔ خانه query مقصد را حذف می‌کرد؛ اکنون pathname و query حفظ می‌شوند.
- ورود از تکمیل پروفایل مقصد خرید را حذف می‌کرد. زنجیرهٔ `login → profile/complete → checkout?service=…&occurrence=…` اکنون با encode جداگانهٔ هر مرحله حفظ می‌شود. helper موجود همچنان مقصد خارجی، protocol-relative، backslash و control character را رد می‌کند.
- helper کوچک مشترک، 401 را به ورود و فقط کد صریح `Backend.privacyConsentRequired` را به پروفایل هدایت می‌کند. 403 عادی و تعارض ظرفیت به خطای رضایت تبدیل نمی‌شوند. ورزشکار به تکمیل پروفایل و بیزینس/ادمین به پروفایل موجود می‌روند.
- QueryError ورزشی همین تصمیم را مصرف می‌کند. در بررسی یکپارچه، لینک مشترک کنار لینک‌های قدیمی فضای عملیات و گفتگو تکرار شد؛ سه نسخهٔ قدیمی حذف و هر سه مسیر بازآزمایی شدند. Retry برای شکست معمول خواندن حفظ شد.
- لینک سیاست داده در عرض ۳۹۰ به دو خط شکسته بود؛ مرکز bounding box روی `P` می‌افتاد و کلیک مرکز ناوبری نمی‌کرد. Enter کار می‌کرد. لینک اکنون یک مستطیل با ارتفاع حداقل ۴۴ پیکسل است؛ کلیک و صفحه‌کلید بررسی شدند. CSS عمومی و اجزای محافظت‌شده تغییر نکردند.

طبق منبع سرور، ConsentGuard فقط درخواست‌های تغییردهنده را بررسی می‌کند و خطای رضایت **409** است. خطای رضایت برای GET مصنوعی اختراع نشد؛ شاخهٔ رضایت آزمون منطق دارد، اما پذیرش مرورگری با خطای واقعی mutation باز است.

## شواهد

[دادهٔ بررسی، hash منابع و شناسهٔ buildها](account-recovery-web-matrix-2026-10-18.json).

- ۲۰ آزمون Node با heap ۱۲۸ MiB و concurrency=1 پاس شدند: مقصد و encode تو‌در‌تو، رد مقصد نامعتبر، تفکیک خطاها، parentهای بازگشت و fixture فقط‌خواندنی.
- lint فایل‌های اپ و هفت فایل UI، قالب، `git diff --check` و محافظ ۵۹ فایل پاس‌اند. lint اول از cwd اپ، فایل‌های UI خارج از base path را نادیده گرفت؛ lint واقعی UI سپس از cwd پکیج با صفر warning اجرا شد.
- build نهایی application، business و admin ترتیبی، با یک worker و heap ۵۱۲ MiB موفق شدند: compile حدود ۸٫۷/۵٫۴/۵٫۳ ثانیه، typecheck حدود ۱٫۶/۲٫۲/۲٫۱ ثانیه و ۶۴/۲۴/۲۰ صفحه. preview و fixture هنگام build خاموش بودند.
- ۱۲ مورد DOM ورود: فارسی/انگلیسی × روشن/تیره × ۳۶۰/۳۹۰/۴۳۰. همه یک main فعال، بدون سرریز و لینک سیاست یک‌تکه با ارتفاع ۴۴ داشتند؛ query مقصد حفظ شد. ماتریس پیش از حذف کنترل‌های قدیمی میزبان اجرا شد؛ منابع ورود تغییر نکردند و پس از build نهایی، مسیر تکمیل پروفایل و ورود فارسی/تیره/۳۹۰ دوباره بررسی شدند.
- کلیک سیاست در فارسی، Enter در انگلیسی و بازگشت هر دو به همان لینک ورودِ دارای مقصد تو‌در‌تو بررسی شد. API عمومی سیاست در fixture پیاده نشده؛ خطای آن شاهد پذیرش محتوای API یا رضایت نیست.
- خدمات، فهرست گفتگو و جزئیات گفتگو در بیزینس هرکدام یک لینک ورود با query کامل داشتند. ورود با صفحه‌کلید از خدمات بررسی شد. شکست خواندن عادی در خدمات یک Retry و صفر لینک ورود داشت.
- عملیات ادمین یک لینک ورود داشت؛ Enter به login با حفظ queue رفت. پارامترهای این بررسی فقط شاهد حفظ مقصد هستند، نه پذیرش عملکرد فیلترها.

fixture جدید `session-expired` فقط GET/HEAD خصوصی را با کد واقعی `Backend.theSessionHasEndedSignInAgain` شبیه‌سازی می‌کند؛ کاتالوگ عمومی خواندنی است. تمام درخواست‌های نوشتنی 405 هستند؛ cookie یا نشست صادر نمی‌شود و OTP، مدرک، سفارش یا رضایتی ثبت نشد.

تصویر نهایی: [ورود فارسی تیره ۳۹۰](screenshots/account-recovery-web-2026-10-18/login-fa-dark-390.jpg). capture اولیه هنگام resize سریع، ۳۶۰ پیکسل بود؛ تصویر با capture ثابت پس از build نهایی جایگزین و ابعاد ۳۹۰×۸۴۴ بررسی شد. ماتریس DOM، پذیرش تمام frameهای paint نیست.

زبان و ظاهر در پایان فارسی/تیره، مطابق شروع، بودند؛ viewport reset، تب‌های ساخته‌شده بسته و همهٔ previewها و fixture این اجرا عادی متوقف شدند.

## بازمانده‌ها

ورود موفق واقعی، ابطال نشست، رضایت نسخه‌دار واقعی و بازگشت پس از ثبت آن، دسترسی میان سازمان‌ها، Secure Storage، دستگاه، staging و پذیرش کامل حرکت و دسترس‌پذیری بازند. بیزینس/ادمین برای بررسی رضایت به پروفایل می‌روند؛ بازگشت خودکار پس از آن در این برش ساخته یا پذیرفته نشده است.

در تنظیماتِ عرض ۴۳۰ و scroll=0، مرکز دکمهٔ ظاهر زیر ناوبری شناور بود؛ کلیک به گفتگو رفت و Enter خود دکمه را فعال کرد. اسکرول و حفاظت focus در برابر ناوبری ثابت نیاز به بررسی مستقل دارد؛ این مشاهده پذیرش دسترس‌پذیری محسوب نمی‌شود. T013، T016، T024، T028 و دروازه‌های PH0 تا PH2 باز می‌مانند.

پیگیری همین روز: Tab واقعیِ تنظیمات کنترل را بالای نوار می‌آورد؛ اصلاحی برای آن لازم نشد. بررسی مستقل، نقص مشابه اما واقعی در حریم خصوصی را پیدا و در محدودهٔ CSS همان صفحه رفع کرد. [نتیجهٔ محدود و معیارهای باز](focus-clearance-web-2026-10-18.md).
