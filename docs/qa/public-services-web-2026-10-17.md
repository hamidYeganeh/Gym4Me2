# خدمات ورزشی — بررسی وبِ فقط‌خواندنی، ۱۷ اکتبر ۲۰۲۶

کاربر در ادامهٔ اختلال Docker صریحاً ادامهٔ بررسی وب را خواست. این برش به PostgreSQL، S3، Docker، staging یا دستگاه دسترسی ندارد. دادهٔ موفق صفحات از fixture مصنوعی HTTP روی loopback می‌آید؛ این نتیجه پذیرش خرید، ظرفیت، عضویت، مجوز یا فاز نیست.

## اصلاح محصول

- فهرست خدمات و metadata جزئیات، مقادیر خالی تاریخ/مربی را بدون جداکنندهٔ اضافه نمایش می‌دهند.
- جست‌وجو `maxLength=160` دارد، مطابق اعتبارسنجی API. تایپ واقعی در مرورگر به ۱۶۰ رسید. `fill` ابزار مقدار ۲۰۰ را تزریق کرد؛ این رفتار با تایپ واقعی یکسان نیست و پذیرش محدودیت براساس آن اعلام نشد.
- جزئیات خدمت اکنون نوع، سطح و تعداد جلساتِ موجود را با `dl/dt/dd` نشان می‌دهد. اعتبار روزانه فقط برای بستهٔ عضویت نمایش داده می‌شود؛ صدور واقعی عضویت از snapshot مدت استفاده می‌کند. عددها با locale قالب‌بندی می‌شوند، از جمله ظرفیت سانس.
- برنامهٔ دوره صریحاً توضیح می‌دهد ثبت‌نام شامل همهٔ جلسات برنامه‌ریزی‌شده است. قرارداد انتخاب occurrence حفظ شد؛ بک‌اند دوره تمام جلسات را در تراکنش تخصیص می‌دهد. این متن تضمین نتیجهٔ رزرو در UI نیست.
- کارت club/coach، جزئیات باشگاه، Kit، رنگ و CSS عمومی تغییر نکردند. guard شامل ۵۹ فایل محافظت‌شده موفق است؛ baseline تصویری کامل این اجزا همچنان معیار جداگانه است.

## fixture و حدود اطمینان

`apps/application/scripts/web-read-fixture.mts` فقط با `GYM_WEB_READ_FIXTURE=true` اجرا می‌شود. Node HTTP سرور روی `127.0.0.1:7488` قرار دارد؛ هیچ اتصال پایگاه داده یا حساب واقعی ندارد. GET/HEAD عمومیِ فهرست، جزئیات و یک تصویر موجود محلی را پاسخ می‌دهد. تمام متدهای نوشتن 405، حساب/هویت خصوصی 401 و مسیر ناشناخته 404 می‌گیرند. Cookie ورودی هویت نمی‌سازد و Set-Cookie صادر نمی‌شود. داده یا درخواست خصوصی ذخیره/لاگ نمی‌شود. شبیه‌ساز پرداخت و بک‌اند production تغییر نکردند.

فهرست و جزئیات عمداً projection متفاوت قرارداد واقعی را دارند: فهرست occurrences/policy ندارد؛ جزئیات nextStartAt ندارد. مبلغ رشتهٔ ریال است؛ نمایش تومان در UI تبدیل می‌شود. پنج خدمت مصنوعی، کلاس با سانس آزاد/پُر/منبع ناموجود، دوره، زمین، بسته و کلاس بی‌برنامه را پوشش می‌دهند. تصویر، asset تصویری موجود است؛ عکس یک باشگاه واقعی ادعا نمی‌شود.

۸ آزمون HTTP fixture پاس شدند: projection، فیلتر و جست‌وجو، ورودی بیش از حد، رد نوشتن و callback، مهمان ماندن، خالی، 503، تصویر ناموجود و تأخیر قابل لغو. این‌ها آزمون خود ابزار QA هستند، نه ۸ سناریوی تجارت PostgreSQL.

فرمان اجرای fixture از `apps/api`، با runtime موجود tsx:

```sh
GYM_WEB_READ_FIXTURE=true WEB_READ_PORT=7488 WEB_READ_SCENARIO=populated \
NODE_OPTIONS=--max-old-space-size=96 \
node --import tsx ../../apps/application/scripts/web-read-fixture.mts
```

حالت‌های `empty`، `unavailable`، `slow` و `missing-image` قابل انتخاب‌اند. همه آزمون HTTP دارند؛ در مرورگر این برش علاوه بر populated، حالت unavailable و missing-image و بازیابی تصویر آزموده شد. empty مستقل و slow در مرورگر اجرا نشده‌اند؛ خالیِ جست‌وجو جدا دیده شد. هیچ fixture در bundle محصول وارد نشده؛ فایل‌ها فقط در scripts/test هستند. بازنویسی API از زمان build است: خروجی ایزوله `.next-qa` این برش با `API_URL=http://127.0.0.1:7488` ساخته شده است. برای اتصال به API واقعی باید دوباره با URL صحیح build شود؛ عوض‌کردن env فرمان start کافی نیست.

## شواهد مرورگر

[ماتریس DOM و رفتار](public-services-web-matrix-2026-10-17.json): ۷۲ مورد یکتا = فهرست و پنج جزئیات × فارسی/انگلیسی × روشن/تیره × ۳۶۰/۳۹۰/۴۳۰. همه یک main فعال و بدون سرریز افقی داشتند؛ شمار لینک‌ها نیز مطابق fixture بود: فهرست ۵، کلاس ۱، دوره ۸، زمین ۱، بسته ۱ و کلاس بی‌برنامه ۰ لینک checkout. این بررسی اندازه‌گیری کنتراست یا مرور بصری تک‌تک ۷۲ مورد نیست.

تصویر کلاس با alt و عرض طبیعی ۱۶۷۲ بارگذاری شد. جست‌وجوی فارسی یک نتیجه، عبارت ناموجود حالت خالی و پاک‌کردن ورودی پنج نتیجه نشان داد. سانس پُر فقط دکمهٔ انتظار و منبع ناموجود هیچ لینک checkout نداشتند؛ درخواست انتظار/checkout ارسال نشد. آخرین جلسهٔ دوره پس از اسکرول در y=599..691 و ناوبری در y=755..828 بود؛ کنترل زیر ناوبری نماند.

در جمع‌آوری ماتریس، یک کلیک تم به Messages رفت؛ ترکیب‌های تکراریِ تیره کنار گذاشته شدند. تغییر تم با Enter از کنترل واقعی تنظیمات و تأیید کلاس DOM انجام شد. دو فراخوانی طولانی تایپ به سقف پنج‌ثانیه‌ای ابزار رسیدند؛ مقدار نهایی با DOM بررسی شد. screenshot دارای clip در صفحهٔ اسکرول‌شده بخش بالای سند را گرفت؛ برای اثبات انتهای صفحه، تصویر مستقل viewport با `fullPage:false` ذخیره شد.

## بازمانده‌ها

جست‌وجوی بی‌نتیجه هنوز متن خالی عمومی دارد و می‌تواند راهنمای اصلاح جست‌وجو داشته باشد. مقایسهٔ تصویری کامل، صفحه‌خوان، بزرگ‌نمایی، reduced-motion، کندی/قطع واقعی، ورود، نوشتن انتظار، پرداخت و ظرفیت واقعی و دستگاه در این برش پذیرفته نشده‌اند. PH0، PH1، PH2 و T016/T042 بسته نمی‌شوند.

## اصلاح و بازآزمایی Retry

در 503ِ فهرست خدمات، فعال‌کردن Retry با Enter، Loading و سپس خطا را نشان داد ولی فوکوس روی BODY افتاد. این خطا با hook مشترک `useQueryRetry` اصلاح شد؛ هم QueryState ورزشکار و هم QueryError پنل‌ها از آن استفاده می‌کنند. دکمه هنگام retry غیرفعال و busy است، درخواست تکراری فوری guard دارد و پس از پایان فقط اگر کاربر کنترل دیگری را انتخاب نکرده و صفحه هنوز فعال است، فوکوس برمی‌گردد. تغییر، خطای واقعی را به حالت خالی تبدیل نمی‌کند.

بازآزمایی نسخهٔ نهایی در فارسی/تیره/۳۹۰، BUTTON فوکوس‌شده و فعال را نشان داد. در اجرای دوم، هنگام Loading با Shift+Tab فوکوس روی لینک اعلان‌ها رفت و پس از خطا همان‌جا ماند. [داده قبل/بعد](public-services-retry-focus-2026-10-17.json) · [تصویر فوکوس](screenshots/public-services-web-2026-10-17/service-retry-focus-fa-dark-390.jpg). این شاهد روی ورزشکار است؛ ماتریس ۱۰۸ خطای بیزینس گزارش قبلی، پیش از استخراج hook بوده و این بار تکرار نشد.

در missing-image، status و Retry نمایش داده شدند و متن/سانس/لینک معتبر باقی ماندند. پس از تعویض fixture به populated، Retry تصویر را با عرض طبیعی ۱۶۷۲ بازیابی کرد. [شاهد خطای تصویر](screenshots/public-services-web-2026-10-17/service-image-unavailable-fa-dark-390.jpg). رفتار فوکوس پس از شکستِ دوبارهٔ تصویر، مجزا از QueryState است و در این برش پذیرفته نشده.

## اعتبارسنجی و پایان اجرا

- ESLint فایل‌های تغییرکردهٔ application و دو فایل hook/QueryError در UI موفق شد. قاعدهٔ React refs ابتدا استفادهٔ یک‌جای شیء hook را رد کرد؛ destructuring در محل مصرف اصلاح شد، بدون خاموش‌کردن قاعده. یک build شروع‌شده پیش از این اصلاح با SIGINT متوقف و با build کامل بعدی جایگزین شد.
- سه build نهایی، ترتیبی و بدون preview/fixture هم‌زمان موفق شدند: application compile۱۴٫۱s، TypeScript۳٫۰s؛ business compile۵٫۷s، TypeScript۴٫۱s؛ admin compile۱۳٫۱s، TypeScript۶٫۲s. heap هر Node۵۱۲MiB، یک worker و Webpack cache خاموش بود. این اعداد سقف peak کل RAM نیستند.
- آزمون HTTP fixture دوباره ۸/۸ موفق شد؛ runtime حدود۵۰۴ms با heap۱۲۸MiB. سپس فقط preview۲۵۶MiB و fixture۹۶MiB هم‌زمان اجرا شدند.
- ۷۲ حالت چیدمان بعد از اصلاح hook دوباره جمع‌آوری شد، نه جمعِ دوبارهٔ موارد قدیمی. buildId سه اپ و hash ده فایل در manifest ثبت است. [بسته انگلیسی/روشن](screenshots/public-services-web-2026-10-17/membership-en-light-390.jpg).
- در پایان زبان فارسی/تم تیره بازگردانده شد، viewport reset و تب موقت بسته شد؛ preview و fixture با SIGINT عادی خاتمه یافتند. هیچ Docker/DB/native اجرا نشد. فضای آزاد حین برش۳٫۹GiB بود؛ فایل یا کش پروژهٔ دیگری حذف نشد.

ادامهٔ fixture: در [برش انتخاب بسته](checkout-memberships-web-2026-10-17.md)، حالت‌های opt-in خواندن DTO عضویت و503 آن اضافه شدند؛ profile/auth و همهٔ نوشتن‌ها همچنان رد می‌شوند. ادعای401 همهٔ مسیرهای حساب در بخش قبلی مربوط به حالت‌های اولیه/پیش‌فرض است، نه این دو شبیه‌سازی query.
