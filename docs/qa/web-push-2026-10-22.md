# Real Web Push · 2026-10-22

Baseline: `53b1ba0`. User requested implementation and activation, not another local notification demonstration. Existing cleared production accounts/catalog must stay cleared.

## Delivery

- Explicitly configured `web-push` provider with one persistent P-256 VAPID pair. Private key and background-job token are server-only Vercel production secrets. No public environment variable, repository file or browser receives either secret.
- Authenticated, application/web-session-bound `/api/v1/profile/push`: status, subscribe, unsubscribe and a rate-limited server test. Client and origin guards remain enforced; subscription and test require current account consent. The public `/api/v1/system/push` returns only provider availability and its public key.
- Additive migration 0036 stores device subscriptions and a durable delivery queue. The existing notification insertion transaction queues future eligible notices only; subscribing never replays history. Stable notification IDs and browser tags collapse repeated attempts. Delivery is at-least-once, not an exactly-once network guarantee.
- Sender uses standard authenticated, encrypted `aes128gcm` Web Push requests. Only opaque binding/notification IDs, version and locale are sent. Message contents, health records, amounts and media URLs are never pushed. Exact browser-vendor host/path validation, HTTPS without credentials/custom ports, short socket timeout and bounded concurrency prevent arbitrary outbound destinations and runaway fanout.
- Delivery rechecks active account, current non-revoked web session, unread/non-retired notice, age and category preference. Missing vendor subscriptions (404/410) are removed; transient network/429/5xx responses retry with bounded backoff; permanent failures stop. A provider acceptance is distinguished from actual device display.
- Logout/session revocation, pending account erasure and suspension remove subscriptions/pending work in the same database transaction. Local session reset clears the non-secret device binding, closes displayed notices and unsubscribes. The service worker serializes binding changes with push/click handling, rejects stale-account payloads and navigates only to the fixed same-origin notification destination. Account exports include device metadata, never endpoint/auth keys; erasure removes devices and cascades delivery records.
- An outer awaited response interceptor dispatches committed notices after the existing domain-jobs interceptor; it does not rely on a recipient tab or an unawaited serverless timer. The ordinary persistent-process worker also drains pending work.
- The existing **public** repository has an opt-in standard Linux Actions workflow, no checkout or repository-token permissions. It calls a dedicated constant-time-token-protected endpoint at minutes 7/22/37/52. The endpoint processes existing due sports jobs and bounded push retries. The 15-minute interval allows Neon to suspend between idle checks; GitHub can delay scheduled runs and disables inactive public-repository schedules after 60 days. This is best-effort scheduling, not exact-time delivery. Forks/private copies remain disabled by workflow guards.

## Device UX and scope

Settings → notification preferences → enable this device. Permission is requested only on the user's click. A subsequent server-test button reports accepted, queued or failure honestly; it does not call `showNotification` locally. Denied permission, unsupported environments, sign-in, network failures and retry are explicit in Persian/English with existing theme components. Turning off clears the local binding before its server request.

This delivery activates **browser/PWA Web Push**. iPhone requires a supported installed Home Screen web app. The current Capacitor APK does not gain native FCM/APNs credentials from a web VAPID key; unsupported native environments direct the user to the supported web version. No Firebase account, paid provider, SMS/payment credentials or new production user was created. Actual OS display requires the device owner's permission and settings.
