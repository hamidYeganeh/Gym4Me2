# قراردادهای مشترک PH1 — ۱۹ اکتبر ۲۰۲۶

T020 پذیرفته شد: DTO، اعتبارسنجی، خطای محلی، صفحه‌بندی و مرزبندی کلاینت PH1 با آزمون و build نهایی بررسی شدند. پذیرش کامل PH0/PH1، UI کاتالوگ، دستگاه و بازیابی مستقل از این معیار جدا و بازند.

## تغییر

تعرفه، حریم خصوصی، تغییر شماره، علاقه‌مندی، سیاست و پیش‌نمایش رسانه از درخواست‌های درون hook به DTO/endpoint/client منتقل شدند. hookها همان کلید کش، scope، signal، invalidation و reset نشست را نگه می‌دارند. ورودی‌های False/Zero، دلیل تغییر و multipart حفظ شدند. پیش‌نمایش ادمین/بیزینس مسیر مستقل دارد.

دو ناسازگاری DTO اصلاح شد: `TeamMemberDto.userId` واقعاً در پاسخ موجود است؛ `AffiliationRecordDto.updatedAt` در جدول/پاسخ وجود ندارد و دیگر اجباری نیست. DTOهای حریم خصوصی در بخش profile و سیاست در system هستند؛ exportهای قبلی حفظ شده‌اند.

همکاری مربی دیگر در۱۰۰ مورد قطع نمی‌شود: API صفحهٔ۱تا۱۰۰۰۰۰ با اندازه۱۰۰ و ترتیب `createdAt DESC, id` دارد. کلاینت `affiliations` همهٔ صفحه‌ها را ترتیبی جمع می‌کند؛ `affiliationPage` یک صفحه را می‌گیرد. collector مشترک، لغو/خطای ادامه/صفحهٔ تکراری را کنترل می‌کند. انتخاب‌گر جغرافیا از همین هسته استفاده می‌کند. سقف بی‌قرارداد۱۰۰ شعبه در aggregate مجموعه نیز برداشته شد؛ ترتیب شعبه با شناسه پایدار شد. تعرفهٔ جاری همچنان سقف دامنه‌ای۱۰۰ طرح دارد که در ایجاد enforce می‌شود؛ تاریخچه صفحه‌بندی مستقل دارد.

پاسخ413 اکنون کد `Backend.payloadTooLarge` و راهنمای فارسی/انگلیسی دارد؛ نام فایل و متن خام خطای parser افشا نمی‌شوند.

DTOهای TypeScript جای validator زمان اجرای همهٔ پاسخ‌ها نیستند؛ collectorها شکل حداقلی و تکرار ID را بررسی می‌کنند. [قراردادهای مسیر و صفحه](../api-conventions.md).

## آزمون واقعی و checks

ابتدا کد/آزمون نوشته و سپس اجرا شد. DB اختصاصی `gym4me_ph1contracts_1a14e17_test` و bucket تصادفی S3 استفاده شدند. API فقط روی پورت تصادفی loopback در آزمون گوش داد؛ دو probe جدا با heap۱۹۲MiB کلاینت‌های ESM واقعی را فراخواندند.

probe تازه با۱۰۱ شعبه و۱۰۱ همکاری مربی، فهرست کامل/صفحهٔ بعد، حساب/نشست، رضایت و export، علاقه‌مندی، رد شمارهٔ فعلی و challenge نامعتبر، ایجاد/بازنگری/وضعیت تعرفه، آپلود/پیش‌نمایش/دریافت S3/حذف، خطای فارسی/انگلیسی، مالکیت و دسترسی ادمین را بررسی کرد. cookieها فقط در محیط فرایند بودند؛ خروجی فقط نتیجه‌های غیرحساس دارد. این شاهد اجرای مرورگر یا دستگاه نیست.

| بررسی | نتیجه |
| --- | --- |
| Jest کاتالوگ واقعی با یک پردازش و اولویت پایین | ۴۲/۴۲، اجرای نهایی۱۹٫۳۱۳ثانیه |
| آزمون‌های وب/adapter native/کلاینت، یک پردازش، heap۱۹۲MiB | ۱۷۹/۱۷۹ |
| قرارداد/localization، بدون Watchman | ۱۳/۱۳ |
| i18n و بررسی متن | ۲/۲ و check-copy موفق |
| types API/کلاینت/UI و lint مرتبط | exit0 |
| محافظ طراحی | ۵۹ فایل بدون تغییر |

جمع۲۳۶ آزمون. اجرای اولیهٔ API در بار آن زمان،۳ timeout۱۵ثانیه‌ای و۳۹ موفق داشت و پذیرفته نشد. اجرای تازه از DB خالی، با مهلت۱۲۰ثانیه برای سناریوی چندمرحله‌ای و۶۰ثانیه برای probe پاس شد؛ مهلت۲۰ثانیهٔ درخواست محصول تغییر نکرد.۱۹٫۳۱۳ثانیه benchmark ظرفیت production نیست.

پوشهٔ آثار از۱۸ اکتبر شروع شد: `.artifacts/ph1-contracts-2026-10-18/`. bucket/objectها و API در teardown بسته/پاک و DB اختصاصی DROP شد. containerهای موجود، دادهٔ اصلی، پیامک زنده و انتشار بیرونی تغییر نکردند.
