# گفتگوی میزبان در بیزینس — ۱۷ اکتبر ۲۰۲۶ (پذیرش باز)

ادامهٔ T069 و PH0/PH2. مسیر و منطق رابط ساخته شده و آزمون سرویس موفق است؛ **QA نهایی رابط و ترنزیشن‌ها تکمیل نشده و این تسک بسته نیست.** نسخهٔ نهایی چیدمان گفتگو در ادامه با پروفایل کم‌مصرف build شد؛ رندر و QA نهایی آن هنوز باز است. [شاهد اجرای سبک](low-resource-execution-2026-10-17.md).

## کد و قرارداد

- `/messages` فهرست صفحه‌بندی‌شدهٔ مختص مجموعه/شعبه، inbox/archive، شمار unread، بارگذاری بیشتر با صفحه‌کلید و حفظ فیلتر در query دارد. گفتگو به ناوبری بیزینس و SportsFrame اضافه شد. دکمهٔ گفتگوی تقویم پس از ساخت/بازیابی همان گفتگو به `/messages/[conversationId]` می‌رود.
- `/messages/[conversationId]` با قرارداد async params نصب فعلی Next ساخته شد. این مسیر مربوط به **وب بیزینس** است؛ shell ثابت native ورزشکار تغییر نکرد. صفحه از hook مشترک پیام، foreground polling، متن/تصویر، سابقه، خواندن/آرشیو/گزارش، اعضا و Sheet تغییر وضعیت استفاده می‌کند. فرم وضعیت، intent/revision را snapshot می‌کند، دلیل و خطای تعارض را نگه می‌دارد و بازخوانی صریح نسخه دارد. این رفتارها در کد موجودند؛ پذیرش مرورگری همهٔ آن‌ها هنوز باز است.
- `GET sports/community/host/conversations/page` به organizationId و branchId معتبر نیاز دارد. مجوز owner/manager همان شعبه پیش از فهرست/cursor کنترل می‌شود. ثبت‌نام شخصیِ پذیرش یا ورزشکار، مجوز میزبان نمی‌سازد. cursor با همان scope و archive بررسی می‌شود.
- `GET sports/community/host/conversations/:id` نقش میزبان را در سرور کنترل می‌کند؛ hook، endpoint و cache جدا از خواندن شخصی دارد. قرارداد جزئیات، organizationId/branchId را برای بازگشت به فهرست همان شعبه ارائه می‌کند. ارسال و مدیریت از مسیرهای موجود و کنترل‌شدهٔ سرور استفاده می‌کنند.
- رنگ/فونت/RTL موجود و Kitهای shadcn حفظ شدند. CSS جدید محدود به host conversation است؛ Kit یا CSS عمومی کارت‌های باشگاه/مربی و جزئیات باشگاه بازنویسی نشد.

## مشاهدهٔ واقعیِ مرورگر تا این نقطه

build QA بیزینس با API مستقل 7288، وب 7383 و دیتابیس `gym4me_business_chat_ui_test` اجرا شد. سه حساب و دو مجموعهٔ fixture، SMS ساختگی و PostgreSQL/S3 محلی استفاده شدند؛ پیامک زنده و پول واقعی در کار نبود.

- ورود مستقیم بدون نشست، پیام فارسی پایان نشست و لینک ورود داشت. مالک مصنوعی با OTP ساختگی وارد شد و به inbox برگشت.
- شعبهٔ بدون گفتگو، حالت خالی داشت. انتخاب شعبهٔ مرکزی در URL ماند؛ reload همان مجموعه/شعبه را نگه داشت.
- ۲۰ ردیف نخست با Enter به **۲۵ ردیف یکتا** رسیدند؛ focus به `host-conversation-c1b0305a-f8b6-4ff7-906b-de6e0a48dcc0`، اولین ردیف صفحهٔ تازه رفت و status شمار ۲۵ را اعلام کرد.
- ورود از گفتگو با ۱۰۱ پیام ساختگی، ۵۰ پیام تازه، میزبان/آرشیو/اعضا، متن فارسی و زمان شمسی را نشان داد. پس از اتمام گذار، یک main فعال بود و سرریز افقی مشاهده نشد. هنوز بارگذاری همهٔ پیام‌های قدیمی، ارسال/تصویر، گزارش، read persist، تغییر وضعیت/تعارض، Backِ Sheet و دسترسی منفی HTTP در مرورگر پذیرش نشده‌اند.
- در بررسی اولیهٔ ۳۹۰×۸۴۴، ناوبری چندردیفی و scopeهای عمودی فضای زیاد می‌گرفتند؛ nav به ردیف قابل‌اسکرول و scopeها به دو ستون تبدیل و build/رندر شدند. متن «شعبهٔ بدون گفتگو» از «گفتگوی بدون پیام» جدا شد. این تغییر، چند ردیف گفتگو را در نمای اول نشان داد.
- بررسی گفتگو نشان داد composer پایین کادر می‌افتد. چیدمان flex با اسکرول داخلی و تنظیم horizontal-only ناوبری در **منبع** اصلاح شد؛ typecheck/lint جدید پاس‌اند، ولی این آخرین اصلاح هنوز build یا پذیرش بصری نشده است. تصویر نسخهٔ قبل به‌عنوان شاهد نهاییِ چیدمان تازه ثبت نمی‌شود.

در viewport این مرورگر، screenshot بدون clip حاشیهٔ اضافی داشت. تصویر با clip هم‌اندازهٔ viewport برای مشاهده استفاده شد؛ برای ماتریس نهایی باید هر بار inner/client dimensions و خروجی واقعی screenshot دوباره کنترل شوند. ماتریس کامل ۳۶۰/۳۹۰/۴۳۰، فارسی/انگلیسی، روشن/تیره و reduced-motion هنوز اجرا نشده است.

## آزمون فنی و ساعت

اجرای اول تجارت **۶۰/۶۹** پاس شد؛ ۹ مورد پرداخت/انتظار به انقضای فوری خوردند. اندازه‌گیری مستقیم:

- میزبان: `2026-10-17T10:27:11.253Z` تا `10:27:11.260Z`
- PostgreSQL: `2026-10-17T09:52:56.378Z`
- اختلاف: حدود **۲٬۰۵۴٬۸۷۹ میلی‌ثانیه عقب‌بودن دیتابیس**.

deadline نگهداری ظرفیت و پیشنهاد در PostgreSQL ساخته می‌شد، ولی startPayment/cash/accept/verify آن را با Date میزبان می‌سنجیدند. اکنون این کنترل‌ها از `clock_timestamp()` دیتابیس **پس از قفل مربوط** استفاده می‌کنند؛ verify همهٔ سانس‌ها را پیش از ارزیابی زمان قفل می‌کند و verified_at هم از ساعت دیتابیس می‌آید. طول مهلت یا شرط آزمون تغییر نکرد. quote و QRِ ساخته‌شده با ساعت میزبان در این برش بازنویسی نشدند.

این اصلاح، سازگاری منطق deadline را تقویت می‌کند؛ **ساعت خراب محیط را درست نمی‌کند و شاهد صحت ساعت کاربر، UI countdown یا readiness staging نیست.** اختلاف ساعت و control plane Docker همچنان مورد عملیاتی بازند.

نتیجهٔ بعدی، **۶۹/۶۹ آزمون تجارت** در `gym4me_business_chat_test`، حدود ۶٫۸۲ ثانیه بود. آزمون‌های انقضای واقعی بدون تغییر پاس ماندند. پوشش تازه شامل pagination میزبان بیش از ۱۰۰ مورد با timestamp دقیق، archive خصوصی، cursor شعبهٔ دیگر، scope نامعتبر، پذیرشِ ثبت‌نام‌شده، ورزشکار، سازمان دیگر و سلب grant مدیر است.

## سایر شواهد و محدودیت‌ها

- API lint/build موفق با منطق زمان و host endpoint فعلی؛ UI typecheck/lint نهایی پس از اصلاح flex/اسکرول نیز موفق‌اند.
- دو آزمون i18n و بررسی copy پس از آخرین متن‌ها موفق‌اند.
- build بیزینس، شامل دو route تازه، دو بار موفق شد؛ اجرای دوم compile حدود ۶٫۷ و types حدود ۴٫۷ ثانیه بود. **این build پیش از آخرین اصلاح flex است.** app/admin/native تازه در این برش ساخته نشدند.
- بار اول build در sandbox به cache پیش‌فرض SWC دسترسی نداشت. طبق [مستند رسمی carrier](https://github.com/swc-project/swc/blob/main/docs/native-addon-carriers.md)، cache خصوصی داخل `.artifacts/swc-native-cache` تعیین شد؛ بررسی امنیت/صحت addon خاموش نشد و نصب package دستکاری نشد. پس از بسته‌شدن سرور وب، فقط همین cache ساخته‌شده در این اجرا برای فضا پاک شد؛ build بعدی باید cache مجاز را دوباره فراهم کند.
- درخواست مجوز یک اجرای تست، پیش از ایجاد process در بازبینی خودکار timeout شد؛ همان درخواست یک بار طبق پیام ابزار retry و تأیید شد. این انتظار یا اجرای ناموفق، شاهد تست موفق محسوب نشد.
- ۵۹ فایل محافظت‌شده و `git diff --check` موفق‌اند. این کنترل جای baseline تصویری تمام کارت‌ها را نمی‌گیرد.

## کمبود فضا و ادامهٔ لازم

فضای دیسک هنگام ویرایش به حدود **۲۱ MiB** رسید و نوشتن فایل رد شد. فایل منبع سالم بود؛ یک backup کامل پیش از ادامهٔ اصلاح در `/private/tmp/gym4me-host-chat-workspace-before-compact-20261017.tsx` نگه داشته شد. پس از حذف cache اختصاصی و بستن preview، فضای مشاهده‌شده همچنان زیر ۱۰۰ MiB بود. cacheهای npm/pnpm و پروژه‌های دیگر، volumeها و تنظیمات امنیتی تغییر نکردند. برای آزادشدن حداقل ۵ GiB از کاربر درخواست کمک شد. کاربر پاسخ داد «فضا آزاد می‌کنم»؛ این پاسخ به معنی آماده‌شدن محیط محسوب نشد. آخرین اندازه‌گیری در ادامهٔ این برش **۱۴۳ MiB** بود؛ فضای کافی هنوز مشاهده نشده است.

API و وب اختصاصی با shutdown عادی خارج شدند. در هر دو DB، users/organizations/services/conversations/messages/notifications/orders/outbox هر هشت صفر تأیید شدند؛ فقط همین دو DB بدون FORCE، پس از کنترل نبود اتصال حذف شدند.

ادامه: build آخرین چیدمان، ورود fixture تازه، آزمون کامل پیام/تصویر/خواندن/آرشیو/گزارش، اعضا و تعارض وضعیت، ایجاد از تقویم، Back و گذار سریع، خطا/کندی و ماتریس زبان/تم/عرض. سپس staging 0029/0030 با بکاپ/بازیابی، دستگاه و دیگر گیت‌های backlog. هیچ فاز یا فروش واقعی/پایلوت با این شاهد بسته نشده است.

پاک‌سازی مرورگر: پس از توقف عمدی وب، تب موقت به صفحهٔ خطای داخلی رفت. ابزار مرورگر reset viewport و close را به‌دلیل URL داخلی رد کرد؛ مسیر جایگزین برای دورزدن محدودیت امتحان نشد. تب deliverable/handoff نشده و موقت است. در نوبت بعد، فهرست تب‌ها بسته‌شدن خودکار تب موقت را تأیید کرد؛ تب اصلی کاربر بسته نشد. reset موفق viewport هنوز تأیید نشده است؛ هنگام preview معتبر بعدی باید پیش از خاموش‌کردن وب انجام شود.

## بررسی دسترس‌پذیریِ callbackهای ناهمگام

برای focus/scroll و تأیید خواندن، helper محدودی در `conversation-target.ts` اضافه شد. مقصد باید متصل، دارای کادر رندر و خارج از `inert` یا `aria-hidden=true` باشد. فوکوس ردیف تازه، textarea پس از ارسال، reason پس از دریافت revision و خطای تعارض و بازگرداندن فوکوس Sheet از این کنترل استفاده می‌کنند؛ بنابراین callback نباید صفحهٔ خروجیِ گذار یا زمینهٔ modal را هدف بگیرد. بازخوانی revision نیز تا پایان، بازکردن دوبارهٔ فرم را غیرفعال می‌کند.

IntersectionObserver خواندن، viewport را root قرار می‌دهد تا clipping اسکرول داخلی و viewport هر دو اعمال شوند. tail عمداً aria-hidden است؛ برای صلاحیت خواندن، سطح والد آن بررسی می‌شود. حالت foreground و نبود modal همچنان شرط‌اند. این‌ها اصلاح منبع‌اند؛ **فوکوس واقعی، صفحه‌خوان، خواندن پس از Back و جابه‌جایی سریع در مرورگر هنوز پذیرش نشده‌اند.**

پس از آخرین اصلاح Sheet و خطای تعارض، `tsc --noEmit --incremental false` بستهٔ UI و ESLint پنج فایل مرتبط با سقف heap برابر ۵۱۲ MiB، هر دو با exit 0 موفق شدند. build کامل و آزمون مرورگر به دلیل فضای دیسک اجرا نشدند.

## اتصال شناسهٔ مسیر در بیزینس

در ادامهٔ بررسی منبع، layout بیزینس `PageTransitions` را بدون `routeId` استفاده می‌کرد؛ اثر `isolateInactiveRoutes` در این حالت از ابتدا return می‌کرد. در نتیجه محافظ focus/read به‌تنهایی نمی‌توانست خارج‌شدن سطح قبلی از دسترس را در طول گذار تضمین کند. اکنون `BusinessProviders` مسیر را با `usePathname` می‌گیرد و آن را به همان wrapper موجود می‌دهد. wrapper تکراری از layout حذف شد. شناسه فقط pathname است؛ organizationId/branchId/view و queryهای دیگر کلید گذار نمی‌شوند.

مستندات نصب‌شدهٔ Next 16.4 در `use-pathname.md` پیش از این تغییر خوانده شد. cacheComponents در تنظیمات بیزینس فعال نیست؛ rewrite موجود هم فقط API است. منطق مشترک SSGOI و اجزای محافظت‌شده تغییر نکردند. typecheck بیزینس با `--incremental false` و ESLint دو فایل تغییرکرده با `--max-warnings 0` هر دو با exit 0 موفق شدند. **رندر سرد، Back، تغییر query و گذار سریع این اتصال هنوز نیازمند build و مشاهدهٔ مرورگرند**؛ خروجی استاتیک TypeScript جای پذیرش حرکت را نمی‌گیرد.

## مانع ادامهٔ اجرای پذیرش

در سه نوبت پیاپیِ بررسی همین مانع، فضای کافی فراهم نشد؛ آخرین اندازه‌گیری **۱۱۵ MiB** است. cache اختصاصی SWC قبلاً حذف شده و cache باقیماندهٔ build QA بیزینس فقط ۲۸۴ KiB است؛ پاک‌کردن آن نیاز ۵ GiB را برطرف نمی‌کند. فرایند build/test منطبق با فرمان‌های همین برش مشاهده نشد و `lsof` نبود listener روی پورت‌های اختصاصی 7288/7383 را تأیید کرد. این وضعیت انتظار برای یک فرایند زنده نیست. هدف تا آزادشدن فضای کافی، مسدود است و هیچ پذیرش یا فازی بسته نشده است. شروع بعدی: اندازه‌گیری فضا، build منبع فعلی، fixture ایزولهٔ تازه و ادامهٔ سناریوهای مرورگری فوق؛ فایل‌ها و کش پروژه‌های دیگر پاک نشدند.

## ادامه با منابع محدود

پس از درخواست کاربر برای مصرف کمتر منابع، فضای ۱٫۲ GiB اندازه‌گیری شد. build نهایی بیزینس با یک worker، heap محدود ۵۱۲ MiB و کش Webpack خاموش موفق شد؛ محافظ‌های جدید و چیدمان flex اکنون شاهد build دارند. build وب ورزشکار و ادمین نیز جداگانه پاس شدند. fixture جدید روی DB خالی به خطای I/O افزونهٔ PostgreSQL برخورد کرد؛ این شکست، شاهد QA مرورگر نیست. [فرمان‌ها و جزئیات محیط](low-resource-execution-2026-10-17.md).

در ادامهٔ همین اجرای سبک، حالت قطع API و Retry/فوکوس در مرورگر اصلاح و پذیرفته شد؛ رفتن به تقویم و Back صفحهٔ خروجی را inert/hidden نگه داشتند و تغییر فیلتر یک سطح مسیر داشت. این پذیرش محدود، جای آزمون گفتگوی دارای داده، Sheet، ارسال تصویر و ماتریس کامل را نمی‌گیرد. تصاویر و جزئیات در گزارش اجرای کم‌مصرف آمده‌اند.
