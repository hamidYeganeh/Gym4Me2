# PH1 / PH0 — فرم پروفایل سه اپ، ۱۹ اکتبر ۲۰۲۶

کد و آزمون توسعهٔ این بخش انجام شد؛ پذیرش کامل T024، PH0 و PH1 باز است. این نوبت **سه سرور توسعه به‌ترتیب** اجرا شدند؛ build تولیدی تازه یا پذیرش native ادعا نمی‌شود.

## اصلاح

`use-profile-editor.ts` منطق مشترک فرم موبایل و فرم پنل را نگه می‌دارد:

- PATCH فقط نام یا نمایش عمومیِ واقعاً تغییرکرده را می‌فرستد؛ ویرایش نام، مقدار قدیمی visibility را دوباره منتشر نمی‌کند.
- بازخوانیِ فیلد تغییرکردهٔ سرور با فرم هماهنگ می‌شود؛ پیش‌نویس فیلد نامرتبط حفظ می‌شود. key دسکتاپ فقط شناسهٔ حساب است؛ تغییر visibility دیگر فرم را بازسازی نمی‌کند.
- پاسخ موفق PATCH خط مبنای فرم را به‌روز می‌کند؛ بازخوانی جدیدتر یا هم‌زمان طبق `Account.updatedAt` مقدم است. این تقدم، برگشت مقدار به حالت اولیه را نیز پوشش می‌دهد. نبود timestamp به تطبیق snapshot مشاهده‌شده محدود است؛ تضمین نسخه‌بندی کامل برای قراردادهای قدیمی ادعا نمی‌شود.
- قفل هم‌زمان پیش از await برقرار و فیلدهای قابل‌ویرایش هنگام ذخیره غیرفعال‌اند. پس از commit، فوکوس به کنترل فعال یا فیلد نام برمی‌گردد؛ مسیر یا فوکوس جدید کاربر رعایت می‌شود.
- نام یک‌نویسه‌ای خطای فارسی/انگلیسیِ دارای `aria-describedby` دارد؛ نام خالی مجاز است. شناسه‌ها برای هر نمونه یکتا و توضیح visibility به کنترل متصل است؛ label پنل حداقل۴۴ پیکسل ارتفاع دارد.

بازبینی استاندارد و spec، remount والد، رسید موفق بدون GET موفق، و race پاسخ قدیمی با خصوصی‌سازی جدیدتر را پیدا کرد؛ پیش از آزمون نهایی رفع شدند. بازبینی اصلاح نهایی یافتهٔ قابل اقدام تازه نداشت. این گزارش security scan کامل نیست.

[HTTP](baselines/ph1-profile-2026-10-19/http.json) فقط درخواست‌های `GET/PATCH /api/v1/profile/account` را ثبت می‌کند؛ شامل۳۳ رخداد و۸ PATCH موفق در این جلسه است. فقط نام فیلدهای payload، طول نام و مقدار visibility نگهداری شده‌اند؛ credential و شماره در این رسید نیست. شکست اتصال وقتی پراکسی خاموش بود پاسخ ثبت‌شده ندارد؛ برای آن status ساختگی گزارش نمی‌شود. سایر endpointها در این ثبت حذف شده‌اند. نسبت‌دادن سناریوها بر توالی دستی این گزارش متکی است و شناسهٔ هم‌بستگی مشترک ندارد.

ورزشکار ابتدا فارسی/تیره در عرض عادی و۳۶۰، سپس انگلیسی/روشن در۳۶۰ بررسی شد. بیزینس فارسی/تیره در۱۲۸۰ و۳۶۰ و ادمین فارسی/تیره در۱۲۸۰ بررسی شدند. این دامنه، ماتریس تمام زبان/تم‌ها، زوم واقعی، صفحه‌خوان یا دستگاه نیست. قطع پراکسی، شبیه‌سازیِ شکست اتصال است؛ قطع شبکهٔ سیستم ادعا نمی‌شود. خصوصی‌سازی هم‌زمان با تغییر کنترل‌شدهٔ DB مدل شد، نه تب واقعی دوم.

## بررسی و پاک‌سازی

- TypeScript پکیج UI با heap۶۴۰ و lint چهار فایل اصلاح‌شده پاس‌اند. اجرای اول TypeScript، نوع state timestamp را ناسازگار یافت؛ پیش از آزمون رابط اصلاح شد و اجرای بعدی پاس است.
- دو آزمون i18n و check-copy پاس‌اند؛۱۰ آزمون ابزار نگاشت/guard نیز پس از تولید گراف تازه پاس‌اند (آزمون واحدِ رفتار فرم محسوب نمی‌شوند). guard وابستگی۱۰ workspace/۸۴۵ فایل، محافظ۵۹ و `git diff --check` پاس‌اند.
- [۸۷۷ ورودی ثبت‌شده](baselines/ph1-profile-2026-10-19/source-inputs.json) کنترل شدند؛۸۷۴ ورودی حین QA ثابت بودند. سه `next-env.d.ts` توسط dev به مسیر `dev/types` تغییر کردند و پس از خاموشی دقیقاً با hash اولیه بازیابی شدند. هیچ ورودی پس از cleanup متفاوت نیست؛ [رسید](baselines/ph1-profile-2026-10-19/verification.json).
- هر نوبت فقط یک frontend با nice10، یک worker پیکربندی‌شده و heap۶۴۰ اجرا شد. سه frontend و API خروج0 داشتند؛ پراکسی نخست برای سناریوی خطا با143 و نمونهٔ آخر با1 متوقف شد. پورت‌های اختصاصی دیگر listener ندارند.
- پس از cleanup، users/organizations/sessions در DB اختصاصی `0/0/0` بودند؛ DB حذف و postgres-test به وضعیت اولیهٔ خاموش برگشت. storage دست‌نخورده ماند. تب‌های سه آزمون بسته و viewport reset شد. اعتبار fixture با حذف DB دیگر قابل استفاده نیست؛ حذف یا بازیابی cookie ورود ادعا نمی‌شود. زبان/تمِ موقت ورزشکار به فارسی/تیره بازگردانده شد.

پذیرش production این کد، خروجی و رفتار native، باقی فلوهای شماره/نشست، QA جامع PH0، CI آنلاین و بازیابی مستقل هنوز لازم‌اند. گراف منبع پیشین۱۹ اکتبر به برش قبل از اصلاح این فرم‌ها محدود است؛ [گراف تازه پس از اصلاح](ph0-route-contracts-profile-2026-10-19.json) مسیر `صفحه → useProfileEditor → useUpdateAccount → PATCH profile/account` را از۴۴۳ فایل منبع ثبت می‌کند. شواهد اجرای پروفایل در همین گزارش‌اند؛ runtimeEvidence داخل JSON فقط شش حالت تاریخی حریم خصوصی را پیوند می‌دهد و پذیرش این سه صفحهٔ جدید از آن نتیجه‌گیری نمی‌شود. تطبیق با build تولیدی نهایی باز است.
