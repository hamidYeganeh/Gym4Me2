# PH2: ماک سامان و چرخه حضور — ۱۵ اکتبر ۲۰۲۶

این برش، پذیرش فنی کل PH2 نیست. ماک سامان پول جابه‌جا نمی‌کند، اطلاعات کارت نمی‌گیرد و سازگاری پروتکل SEP را ادعا نمی‌کند. آداپتر با توکن DI قابل تعویض است و در `NODE_ENV=production` غیرفعال می‌شود. ایجاد تلاش پرداخت کلید idempotency دارد؛ verify/query سمت سرور انجام می‌شود. endpoint مستقل `POST /api/v1/sports/payment-callbacks/saman-mock` فقط proof امضاشدهٔ HMAC را می‌پذیرد، پاسخ آن اطلاعات سفارش را برنمی‌گرداند و همان تلاش اشاره‌شده را روی سرور تأیید می‌کند؛ امضا هرگز به مرورگر داده نمی‌شود. شکست پیش از انقضای hold اجازه تلاش جدید می‌دهد؛ همان کلید نتیجه همان تلاش قبلی را برمی‌گرداند. پرداخت دیررس به وضعیت بررسی و استرداد می‌رود.

بلیت رزرو از دو ساعت پیش از شروع تا پایان جلسه صادر و هنگام اسکن دوباره با وضعیت جلسه و پرداخت بررسی می‌شود. ورود و خروج ساختمان جدا ثبت می‌شوند؛ خروج تکراری نتیجه نخست را برمی‌گرداند و کارکنان شعبه دیگر مجوز ندارند. worker پس از پایان جلسه، رزرو قطعیِ بدون حضور را یک‌بار غیبت می‌زند و اثر مانده بسته را از سیاست snapshot همان سفارش می‌گیرد. حضور دستی همچنان با دلیل و audit مسیر مستقل دارد.

در پوستهٔ Luma، تغییر callback فرم دیگر تاریخچهٔ Sheet را دوباره push نمی‌کند. فوکوس صفحه‌کلید روی کنترل‌های جدید مشخص است، متن تب‌ها و وضعیت‌ها بزرگ‌تر شده و حالت reduced-motion blur ناوبری را حذف می‌کند. نمایش تومان با تقسیم صحیح ریال و یک‌دهم تومان انجام می‌شود تا باقیماندهٔ ریال بی‌صدا حذف نشود.

صف گزارش گفتگو در admin اکنون دو تصمیم دلیل‌دار و نسخه‌دار دارد: رد گزارش یا حذف پیام از نمایش. متن گزارش فقط برای ادمین مجاز قابل مشاهده است و تصمیم در audit ثبت می‌شود.

صف مدارک در پنل بیزینس به خدمت متصل شد: مسئول مجاز مدرک را با URL کوتاه‌مدت باز می‌کند، دلیل می‌نویسد و نسخهٔ دیده‌شده را تأیید یا رد می‌کند. migration `0018` ستون revision و زمان بررسی را اضافه می‌کند؛ تصمیم و audit در یک تراکنش انجام می‌شوند، نقش سازمان دوم رد می‌شود، تصمیم کهنه خطای تعارض می‌دهد و مدرک منقضی تأیید نمی‌شود. آزمون سرویس و migration روی PostgreSQL ایزوله پاس شدند؛ آزمون دستی رابط بیزینس هنوز باز است.

در اپ ورزشکار، قرارداد typed مدرک به `@repo/api` منتقل شد و URL پیش‌نمایش فقط در زمان درخواست کاربر گرفته می‌شود؛ کنترل تازه‌کردن لینک برای URLهای ۶۰ثانیه‌ای وجود دارد. build اپ ورزشکار پس از این تغییر پاس شد.

شواهد این نوبت: ۲۳ آزمون تجارت روی PostgreSQL ایزوله پاس، از جمله callback تکراری، امضای نامعتبر، عدم تأیید تلاش دیگر و منع دسترسی مالک سازمان دوم به سند، گفتگو و گزارش مالی سازمان اول؛ typecheck API، application و UI و lint فایل‌های API پاس؛ build API و application با webpack و export native پس از تغییرات نهایی موفق؛ build دو وب دیگر پیش از افزودن callback موفق؛ کنترل هش ۵۹ فایل محافظت‌شده پاس. چهار آزمون backup/worker/alert/association نیز پاس شدند. اجرای پیش‌فرض Turbopack در sandbox محلی هنگام bind worker CSS متوقف شد؛ build webpack موفق است. آزمون دستی دستگاه، remote CI، ممیزی تصویری کامل و فروش واقعی همچنان بازند.

بازآزمایی ۱۶ اکتبر: اسکریپت ترتیبی `scripts/verify-ph1.sh` همهٔ ۱۴۱ آزمون PH1 را با موفقیت اجرا کرد. build بیزینس و API پس از اضافه‌شدن صف مرور مدارک و migration 0018 نیز پاس شدند. هشدار deprecation مربوط به استفادهٔ هم‌زمان از یک client در `pg` در خروجی تست کاتالوگ دیده شد و برای بازبینی فنی باقی می‌ماند.

دو [baseline تصویری صفحه باشگاه](baselines/README.md) در فارسی روشن/تیره و عرض دسکتاپ ثبت شدند. کارت‌ها، انگلیسی و عرض موبایل همچنان برای baseline لازم‌اند.
