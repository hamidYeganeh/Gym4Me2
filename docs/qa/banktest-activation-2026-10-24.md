# فعال‌سازی اعتبار بانک تست — ۲۴ اکتبر ۲۰۲۶

پس از خرید اعتبار توسط کاربر، پذیرندهٔ Gym4Me در پنل BankTest با وضعیت «فعال» و تاریخ انقضای ۱۴۰۵/۰۹/۰۲ مشاهده شد. شناسهٔ آن با پذیرندهٔ اتصال قبلی تطبیق دارد. تنظیمات API آنلاین از قبل `PAYMENT_PROVIDER=saman_sandbox` بود و انتشار `dpl_7TBcX5aKaSm3MmfEVcfvqLmYjQCx` در وضعیت `READY` قرار داشت؛ انتشار مجدد لازم نبود. تنظیمات خصوصی API محلی نیز برای همین پذیرنده تنظیم شد.

## آزمون تازه پس از خرید

- یک حساب مصنوعی و نشست کوتاه‌مدت فقط در دیتابیس دارای نشانگر `isolated-demo-v1` ساخته شد؛ پیامکی ارسال نشد.
- سفارش تازهٔ ۲٬۲۰۰٬۰۰۰ ریالی از API آنلاین ایجاد و به درگاه فعال BankTest هدایت شد. تکرار فرمان، همان تلاش و همان توکن را برگرداند؛ تأیید پیش از callback، سفارش را پرداخت‌شده نکرد.
- سناریوی موفق از صفحهٔ واقعی شبیه‌ساز در مرورگر ثبت و callback به API آنلاین ارسال شد. Verify سمت سرور، سفارش `paid` و رزرو `confirmed` را ثبت کرد؛ دقیقاً یک سند پرداخت و یک رسید بانکی وجود داشت.
- لغو همان رزرو، Reverse کامل را اجرا کرد. سفارش `refunded`، رزرو `cancelled` و مبلغ برگشت برابر کل مبلغ سفارش شد. پنل پذیرنده نیز Verify و Reverse موفق را برای تراکنش تازه نشان داد.
- نشست آزمون ابطال و حساب مصنوعی معلق شد. هیچ رزرو فعالی از این آزمون باقی نماند.
- ۱۸ آزمون واحد اتصال سامان، callback و مرز محیط شبیه‌ساز در سه مجموعه موفق شدند.

شواهد در مسیر محلی نادیده‌گرفته‌شدهٔ `.artifacts/banktest-activation-2026-10-24/` هستند: `order-start-proof.json`، `order-paid-proof.json`، `order-refund-proof.json` و `banktest-verified-reversed.png`. توکن‌ها و اطلاعات اتصال در این گزارش ثبت نشده‌اند.

این آزمون فقط شبیه‌ساز بانک تست است و پول واقعی جابه‌جا نکرد. تکمیل برگشت به اپ نصب‌شده روی گوشی فیزیکی در این آزمون بررسی نشد.
