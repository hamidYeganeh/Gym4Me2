# مستندات محصول Gym4Me

نسخهٔ ۱ · وضعیت بررسی‌شده در ۲۰۲۶/۱۰/۱۱ · مالک محصول و مسئولان اجرایی هنوز به افراد مشخص واگذار نشده‌اند.

Gym4Me مسیر پیدا کردن خدمت ورزشی، خرید، رزرو، حضور و ادامهٔ تمرین را به هم وصل می‌کند. مربی و ورزشکار یک اپ مشترک دارند؛ باشگاه‌ها در بیزینس کار می‌کنند و تیم پلتفرم پنل ادمین دارد.

## روش پیگیری

- شناسه‌های M01 تا M16 متعلق به فیچرها، FL01 تا FL22 متعلق به فلوها و Txxx متعلق به تسک‌ها هستند.
- PH0 تا PH6 فازهای اجرای دامنهٔ اصلی‌اند؛ PH7 ایده‌های تکمیلی است. شمارهٔ فاز، وابستگی اجباری به تمام فازهای قبل ایجاد نمی‌کند.
- علامت `[x]` فقط یعنی خروجی همان تسک با شاهد موجود است. علامت `[ ]` یعنی هنوز پذیرش نشده؛ به‌تنهایی به معنی شروع‌نشده یا مسدود نیست.
- وضعیت تسک فقط در backlog نگهداری شود؛ تیک‌های flows و roadmap مربوط به پذیرش فلو و دروازهٔ انتشارند و باید جداگانه بررسی شوند.
- در هر تغییر، شناسه را ثابت نگه دارید و سند، API یا تست شاهد را به همان تسک اضافه کنید. شمارهٔ فاز یا اولویت می‌تواند تغییر کند.
- پایان تسک شامل مسیر خطا، دسترسی، قرارداد API و بررسی مناسب همان تغییر است؛ تعریف کامل در انتهای backlog آمده است.

## مبنای این نسخه

این بسته از تصمیم‌های همین گفتگو، شرح قبلی ۱۶ ماژول و بررسی فایل‌های فعلی ساخته شده است. تصمیم‌های قطعی کاربر: همهٔ قابلیت‌های اصلی در دامنه بمانند؛ مربی و ورزشکار در یک اپ باشند؛ پنل باشگاه بیزینس باشد؛ PostgreSQL استفاده شود؛ API از الگوی نسخه‌دار domain/feature پیروی کند.

ارائه‌دهندهٔ پیامک کاوه‌نگار با الگوی `g4m-otp` انتخاب شده است. زمان تحویل، ترکیب تیم، شهر شروع، ارائه‌دهندهٔ پرداخت، قرارداد تجهیزات و قیمت پلن‌ها هنوز تعیین نشده‌اند. فازبندی این سند پیشنهاد اجرایی است؛ آمار بازار، زمان‌بندی قطعی یا قابلیت تحویل‌شده را ادعا نمی‌کند.
