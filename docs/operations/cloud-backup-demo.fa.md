# بکاپ و بازیابی دموی ابری

این مسیر فقط برای نصب موجود با marker برابر `isolated-demo-v1` است. با حذف guard اسکریپت، آن را روی دیتابیس دیگری اجرا نکنید. بکاپ شامل دیتابیس و رسانه‌های `gym4me_demo_media` است؛ bucket بیرونیِ نصب دیگری را پوشش نمی‌دهد.

## محل و زمان‌بندی

- workflow: `.github/workflows/cloud-backup.yml` روی شاخهٔ اصلی.
- snapshot کامل: ساعت‌های ۰۰، ۰۶، ۱۲ و ۱۸، دقیقهٔ ۱۳ UTC.
- دفتر حذف: دقیقه‌های ۱۳، ۲۸، ۴۳ و ۵۸ UTC. GitHub ممکن است اجرای schedule را عقب بیندازد؛ زمان‌بندی تضمین تحویل یا RPO نیست.
- artifact رمزگذاری‌شده در GitHub Actions، با نگهداری ۳۰ روز. نام آن شامل شناسهٔ run است. مخزن عمومی است؛ محرمانگی به رمزگذاری وابسته است و نباید plaintext یا کلید خصوصی در artifact قرار گیرد.
- secret خواندن مبدا: `GYM_BACKUP_DATABASE_URL` در GitHub. نقش مجزا فقط SELECT و USAGE روی public و drizzle دارد؛ مجوز ایجاد schema یا تغییر داده ندارد. default privilege برای جدول‌های آینده تنظیم شده است.
- گواهی PostgreSQL با `verify-full` بررسی می‌شود. pg_dump در Docker از CA خواندنی میزبان استفاده می‌کند. در صورت خطای CA، اعتبارسنجی TLS را خاموش نکنید.

اسکریپت snapshot خواندنیِ repeatable-read صادر می‌کند؛ dump و شمارش رسانه از همان snapshot هستند. دفتر حذف نیز فقط داده‌های قابل مشاهده تا زمان همان snapshot را می‌گیرد. سربرگ و بدنهٔ آرشیو با X25519، HKDF-SHA256 و AES-256-GCM احراز می‌شوند. شکست احراز، فایل plaintext نهایی باقی نمی‌گذارد.

## نگهداری کلید

فایل `scripts/backup-recipient.public-key` عمومی است. کلید خصوصی این نصب در `.ops-private/cloud-backup/recovery-key.pem` با مجوز ۶۰۰ و یک کپی رمزگذاری‌شده در تنظیم production پروژهٔ API در Vercel با نام `BACKUP_RECOVERY_PRIVATE_KEY` نگهداری می‌شود. هیچ متغیر `NEXT_PUBLIC_*` برای آن مجاز نیست. مالکِ دارای دسترسی به Vercel می‌تواند در صورت از دست‌رفتن مک، کلید را به یک فایل خصوصی در محیط بازیابی انتقال دهد؛ آن را در چت، issue، log یا مخزن نگذارد.

تعویض کلید، بکاپ‌های قبلی را دوباره رمزگذاری نمی‌کند. کلید قبلی باید تا پایان عمر آخرین بکاپ مربوط به آن نگه داشته شود. پیش از تعویض recipient، یک capture و بازیابی موفق با کلید جدید لازم است.

## بازیابی در قرنطینه

۱. یک full artifact و جدیدترین دفتر حذفِ معتبر و مستقل از آن را دریافت کنید. زمان capture را از manifest بخوانید؛ زمان دانلود جای آن را نمی‌گیرد. در صورت نبود دفتر به‌روز، نسخهٔ بازیابی‌شده آفلاین می‌ماند.

۲. محیطی خصوصی و جدا از سرویس عمومی بسازید. هیچ app، worker یا cron به آن وصل نباشد. دسترسی خروجی به بانک، پیامک، FCM و APNs بسته باشد. کلیدها و URLهای تولید را برای context بازیابی کپی نکنید.

۳. با `decryptBackup(source, destination, privatePem)` از `scripts/encrypted-backup.mjs` آرشیو را احراز و رمزگشایی کنید. destination باید تازه باشد. فقط اعضای `manifest.json`، `deletion-ledger.json` و `database.dump` برای full و دو فایل JSON برای ledger انتظار می‌روند. مسیرهای آرشیو را پیش از extract کنترل کنید و فایل‌ها را با مجوز خصوصی نگه دارید.

۴. dump را با PostgreSQL سازگار در دیتابیس تازه و با `--no-owner --no-acl` بازیابی کنید. تعداد migrationها، جدول‌های اصلی، تعداد و بایت رسانه را با manifest و رسید capture مقایسه کنید. migrationهای جدید فقط روی همین نسخهٔ قرنطینه تمرین شوند؛ reset یا seed مبدا بخشی از بازیابی نیست.

۵. برای replay، `DATABASE_URL` باید صریحاً به دیتابیس قرنطینه اشاره کند و context فاقد worker فعال باشد (`NODE_ENV=test` و `RETENTION_ENABLED=false`). command موجود ابتدا dry run دارد:

```text
pnpm --filter api data:deletion-ledger replay PRIVATE_LEDGER SNAPSHOT_ISO
pnpm --filter api data:deletion-ledger replay PRIVATE_LEDGER SNAPSHOT_ISO --apply
```

`PRIVATE_LEDGER` باید متعلق به همان کاربر سیستم، بدون symlink، حداکثر ۱۰ MiB و با مجوز ۶۰۰ باشد. دفتر باید معتبر، تازه و مربوط به زمانی پس از snapshot باشد. موفقیت command با دفتر قدیمی یا نبود اطلاعات کافی دربارهٔ حذف‌های جدید، مجوز آنلاین‌کردن نیست.

۶. پس از replay، رسانهٔ مجاز، نشست‌ها، صف‌های قدیمی، readiness و مسیرهای اصلی را در محیط جدا بررسی کنید. پیش از اتصال عمومی، پوشش آخرین حذف‌ها، کنترل دسترسی و مقصد سرویس‌های بیرونی باید دوباره تأیید شود. فایل‌های خام موقت پس از پایان تمرین پاک شوند؛ بکاپ رمزگذاری‌شده و رسید غیرحساس حفظ شوند.

## مرز فعلی و شواهد

ثبت مستقل و هم‌زمان حذف پیش از پاسخ موفق به کاربر هنوز پیاده نشده است. schedule دفتر حذف جای این ضمانت را نمی‌گیرد؛ این مسیر ادعای بازیابی بدون از دست‌رفتن داده یا آماده‌بودن عرضهٔ عملیاتی ندارد. دریافت هشدار خرابی توسط یک مسئول واقعی نیز هنوز تأیید نشده است.

[گزارش اجرا، بازیابی و مهاجرت](../qa/completion-2026-10-25.md) شامل شناسهٔ CI، artifactها و مرزهای پذیرش است. source URL، کلید خصوصی و دادهٔ کاربران در این سند قرار نمی‌گیرند.
