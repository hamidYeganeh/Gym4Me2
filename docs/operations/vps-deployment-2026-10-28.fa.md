## سرویس‌ها و دسترسی

API و چهار فرانت‌اند با systemd و restart خودکار اجرا می‌شوند. PostgreSQL 18
و SeaweedFS با Docker Compose، volume پایدار و restart خودکار اجرا می‌شوند.
پورت دیتابیس `55432`، ذخیره‌سازی `8333` و پورت‌های برنامه فقط روی loopback بازند.
فایروال SSH/HTTP/HTTPS را اجازه می‌دهد. پس از reboot، همهٔ سرویس‌ها خودکار
بالا آمدند و واحدهای مربوط به پروژه سالم بودند.
واحد پایهٔ `cloud-init-hotplugd` پس از boot برای تشخیص یک MAC در metadata خطا
ثبت کرده است؛ شبکهٔ اصلی و سرویس‌های پروژه در آزمون‌های بعد از boot سالم‌اند.

کلید اختصاصی SSH در `~/.ssh/gym4me_prod` ذخیره شده؛ اتصال محلی `ssh gym4me-vps`
است. ورود SSH با رمز غیرفعال است. رمز اضطراری کنسول و نسخهٔ خصوصی تنظیمات
در `.ops-private/` با دسترسی محدود نگهداری می‌شوند و وارد snapshot عمومی نشده‌اند.
تنظیمات سرور در `/etc/gym4me/` فقط برای root قابل خواندن‌اند.

نقش runtime دیتابیس از نقش migration و مدیر دیتابیس جداست. API به loopback
محدود است؛ `TRUST_LOOPBACK_PROXY=true` همراه با بازنویسی X-Forwarded-For توسط
Nginx مانع مشترک‌شدن محدودیت IP کاربران می‌شود. این قابلیت در کد به‌صورت
پیش‌فرض خاموش است و فعال‌سازی آن با bind عمومی پذیرفته نمی‌شود.

## کلیدها و اتصال سرویس‌ها

کلیدهای بیرونی از envهای همین پروژه به تنظیمات سرور منتقل شدند. رمز دیتابیس،
کلید نشست و اعتبار ذخیره‌سازی مختص استقرار جدید ساخته شدند.

| سرویس | شاهد اتصال |
| --- | --- |
| کاوه‌نگار | دریافت اطلاعات حساب موفق؛ اعتبار موجود؛ پیامک آزمایشی ارسال نشد |
| FCM | درخواست `validate_only` موفق؛ اعلان تحویل داده نشد |
| نشان | دریافت tile واقعی با کلید وب و Origin اپ موفق |
| سامان | ساخت توکن BankTest موفق؛ پرداخت انجام نشد |
| ذخیره‌سازی | HeadBucket و readiness موفق |

پرداخت همچنان `saman_sandbox` است؛ کد فعلی به BankTest متصل می‌شود.
موفقیت اعتبارسنجی FCM شاهد نمایش اعلان روی دستگاه واقعی نیست.

## پذیرش و بکاپ

- بیلد API و هر چهار برنامه روی Linux موفق شد؛ بررسی TypeScript هر چهار برنامه روی دستگاه توسعه نیز موفق بود.
- ۲۳ مجموعه و ۱۶۰ تست واحد API پاس شدند، شامل اعتماد محدود به پراکسی و رد IP جعلی در زنجیرهٔ درخواست.
- سایت و اپ در Chrome با فونت، تصویر و استایل مشاهده شدند.
- هر چهار فرانت‌اند پاسخ HTTP 200 دادند؛ readiness دیتابیس و storage را up گزارش کرد.
- دریافت ۱۰۲ فایل استاتیک Next.js از چهار دامنه با HTTPS موفق بود.
- درخواست بدون نشست 401، Origin نامعتبر 403 و Swagger غیرفعال 404 برگرداند.
- هر ۶۵ migration اجرا شدند. دیتابیس این سرور از ابتدا ایجاد شده است.
- بکاپ روزانهٔ دیتابیس ساعت ۰۲:۰۰ تهران با حداکثر پنج دقیقه تأخیر تصادفی و نگهداری هفت‌روزه فعال است.
- بازیابی بکاپ اولیه در دیتابیس موقت موفق بود؛ نسخه‌ای از آن در `.ops-private/vps/initial-database.dump` ذخیره شد.
- بکاپ روزانه در همین VPS است؛ همگام‌سازی خودکار خارج سرور و بکاپ فایل‌های آپلودی هنوز تنظیم نشده‌اند.
